# RESTful API 설계, 처음부터 쉽게

> 발표: 2026-10-16(금) 13:30 · 이재웅(AIGJ_01_012) · 10~15분
> 대상: 비전공자, 신입 개발자. "API가 뭔지는 대충 들어 봤다" 정도면 충분합니다.

이 저장소는 **RESTful API 설계**를 처음 배우는 사람이 순서대로 읽으며 공부할 수 있게 정리한 자료입니다. 모든 예시는 하나의 이야기로 이어집니다. **블로그 서비스의 API**(글, 댓글, 회원)를 함께 설계해 봅니다.

## 한 문장 요약

> **REST란 "무엇을(자원)은 URL로, 어떻게(행동)는 HTTP 메서드로, 결과는 상태 코드로" 표현하자는 약속입니다.**
> 이 약속을 잘 지키면, 처음 보는 사람도 API를 보고 바로 쓸 수 있습니다.

## 이 자료에서 쓰는 예시: 블로그 API

| 하고 싶은 일 | 요청 | 결과 |
|---|---|---|
| 글 목록 보기 | `GET /api/v1/posts?page=0&size=20&sort=createdAt,desc` | `200 OK` + 글 목록 |
| 글 하나 보기 | `GET /api/v1/posts/42` | `200 OK` + 글 / 없으면 `404 Not Found` |
| 글 쓰기 | `POST /api/v1/posts` | `201 Created` + 새 글 주소 |
| 글 일부 수정 | `PATCH /api/v1/posts/42` | `200 OK` + 고친 글 |
| 글 지우기 | `DELETE /api/v1/posts/42` | `204 No Content` |
| 글의 댓글 보기 | `GET /api/v1/posts/42/comments` | `200 OK` + 댓글 목록 |
| 댓글 쓰기 | `POST /api/v1/posts/42/comments` | `201 Created` |
| 좋아요 누르기 | `PUT /api/v1/posts/42/likes/me` | `204 No Content` |
| 좋아요 취소 | `DELETE /api/v1/posts/42/likes/me` | `204 No Content` |

이 표를 보고 "무슨 일을 하는지 바로 알겠다"는 느낌이 들면, 그게 바로 RESTful한 설계입니다.

## 예시 코드에 대해

- 서버 코드는 **Java 21 + Spring Boot 3 이상**을 기준으로 씁니다. 다른 언어여도 원리는 같습니다.
- 코드가 처음이라면 코드 블록은 건너뛰고 설명과 표만 읽어도 됩니다.

## 참고한 기준

- RFC 9110 *HTTP Semantics*: HTTP 메서드와 상태 코드의 공식 정의
- RFC 9457 *Problem Details for HTTP APIs*: 에러 응답 표준 형식 (예전 RFC 7807을 대신함)
- OpenAPI Specification: API 문서 표준
- Roy Fielding, *Architectural Styles and the Design of Network-based Software Architectures* (2000): REST가 처음 나온 논문
